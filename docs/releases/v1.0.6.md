**A tool that decides what is safe should check what it trusts — the file it is handed, the programs it runs, and the evidence it keeps.**

v1.0.5 applied the project's own rules to its release pipeline. This release applies them to the program itself, after a code-level review against OpenSSF Scorecard, OWASP ASVS, NIST SSDF, ISO/IEC 27001, CIS Controls and ISO/IEC 27037. Every fix below has a test, and the tests were checked by reverting each fix and watching them fail.

## The gate checks the file it is given

`gate` now recomputes the result hash, the finding counts and the risk score from the findings and refuses (exit `2`) a `scan-result.json` that disagrees with itself. This catches hand edits, truncated files and files from another scoring model. It is a consistency check, **not a signature**: someone who can recompute every field is not stopped. `--skip-integrity-check` turns it off and says so each time.

A suppression whose `expires` cannot be read (`2026-13-45`, `tomorrow`) used to apply forever. It is now not applied, and the gate says so.

## The scanners are third-party programs, and the report says which one ran

- Each `scanner_runs[]` entry records the binary's path, where it was found (`path` or `tools`) and its SHA-256. PATH is searched before `~/.tatar-kuber/tools`, so a pinned scanner can be shadowed; that now produces a warning, stored in the run.
- `update` records the SHA-256 of what it unpacked (`installed_sha256` in `tools.lock.yaml`). If the binary in the tools directory has changed since, the scanner is reported `unavailable` and is **not run**.
- Forge and CI credentials (`GITHUB_TOKEN`, `GH_TOKEN`, `ACTIONS_*` …) are no longer handed to scanners; `TATAR_PASS_ENV` names exceptions. `TATAR_STRICT_ENV=1` switches to an allow-list that also withholds cloud credentials.
- Checkov runs with `BC_SKIP_MAPPING=TRUE`; without it, it called `api0.prismacloud.io` on every run.
- Kubescape and Popeye were measured on a kind cluster with a logging DNS resolver. Popeye talks only to the API server. Kubescape also reaches `github.com`, `release-assets.githubusercontent.com` and `tuf-repo-cdn.sigstore.dev`, and a version-check service on every run. The version check is now switched off (`KS_SKIP_UPDATE_CHECK=true`) and `--keep-local` keeps results off any Kubescape account. Only destinations were observed, not request contents.
- Trivy's raw secret match is no longer copied into findings.

## Evidence and inputs

- `scan` writes `raw/SHA256SUMS` in `sha256sum` format, and `scan --raw-dir` refuses a directory whose files were edited, truncated or added after the scan. A directory without the manifest (collected by hand) still loads.
- Scanner output, raw JSON and scan results are capped at 256 MiB, and policy, attestation and registry files at 16 MiB. A larger file is an error, never a truncated read.
- A kube context, namespace or path that starts with `-` is refused instead of being passed to a scanner as a flag.
- `update` validates the version in the lock before it goes into a download URL, writes `tools.lock.yaml` atomically, and keeps the old install until the new one is in place.
- HTML and audit reports carry a restrictive Content-Security-Policy, and Chromium gets `--no-sandbox` only as root or inside a container.
- Nine fuzz targets cover the four scanner parsers, the policy and attestation files, the registry and the lock file.

## The project's own supply chain

- Every GitHub Action is pinned to a commit SHA (first-party included), workflows are read-only by default with write permission only on the job that needs it, container base images are pinned by digest, and the repository setting that rejects unpinned actions is on.
- CI installs the scanners with `tatar-kuber update` — pinned versions, verified checksums — instead of piping install scripts to a shell.
- The GitHub Action's `version` default is a release tag, not `latest`.
- `SECURITY.md` explains how to report a vulnerability privately.

## Documentation

The README is shorter and says what the tool does, how to try it and where to go next. The command reference, CI gate adoption, the security model and scope moved to guides in `docs/`, in English and Mongolian.

## Behaviour changes to know about

- `gate` exits `2` on a result that is inconsistent with itself (was: accepted).
- `scan --raw-dir` exits `2` on a directory that no longer matches its `SHA256SUMS`.
- A suppression with an unreadable `expires` no longer applies.
- A scanner whose installed binary changed after `update` is not run.
- `doctor` and `scanner_versions` show `unparsed` when a scanner prints a version line without a version number.

# Монголоор

**Юу аюулгүй вэ гэдгийг шийддэг хэрэгсэл өөрийн итгэдэг зүйлээ шалгах ёстой — хүлээн авсан файл, ажиллуулдаг програм, хадгалдаг нотолгоо.**

v1.0.5 төслийн өөрийн дүрмийг release pipeline-д хэрэглэсэн. Энэ хувилбар тэр дүрмийг програмд өөрт нь хэрэглэв: OpenSSF Scorecard, OWASP ASVS, NIST SSDF, ISO/IEC 27001, CIS Controls, ISO/IEC 27037-той тулгасан кодын түвшний шалгалтын дараа. Доорх засвар бүр тесттэй бөгөөд засвар бүрийг буцааж, тест унахыг нь харж баталгаажуулсан.

## Gate өөрт өгсөн файлаа шалгана

`gate` нь result hash, finding-ийн тоо, эрсдэлийн оноог findings-ээс дахин бодож, өөртэйгөө зөрсөн `scan-result.json`-оос татгалзана (exit `2`). Гар засвар, таслагдсан файл, өөр оноолтын загвараар үүссэн файлыг барина. Энэ бол тууштай байдлын шалгалт, **гарын үсэг биш**: бүх талбарыг дахин бодож чадах хүнийг зогсоохгүй. `--skip-integrity-check` үүнийг унтрааж, тухай бүрд мэдэгдэнэ.

`expires` нь уншигдахгүй (`2026-13-45`, `tomorrow`) suppression өмнө нь үүрд хүчинтэй байв. Одоо хэрэглэгдэхгүй, gate үүнийг мэдэгдэнэ.

## Scanner бол гуравдагч талын програм; тайлан аль нь ажилласныг хэлнэ

- `scanner_runs[]` бичлэг бүр binary-ийн зам, хаанаас олдсон (`path` эсвэл `tools`), SHA-256-г хадгална. PATH нь `~/.tatar-kuber/tools`-оос өмнө хайгддаг тул пиннэсэн scanner-ийг далдалж болно; одоо үүнд анхааруулга гарч run-д хадгалагдана.
- `update` нь задалсан binary-ийн SHA-256-г (`tools.lock.yaml`-ийн `installed_sha256`) бичнэ. Tools хавтас дахь binary дараа нь өөрчлөгдсөн бол scanner `unavailable` гэж гарч **ажиллахгүй**.
- Forge/CI credential (`GITHUB_TOKEN`, `GH_TOKEN`, `ACTIONS_*` …) scanner-т дамжихаа больсон; `TATAR_PASS_ENV` нь онцгойлон нэрлэнэ. `TATAR_STRICT_ENV=1` нь cloud credential-ийг ч хаах allow-list болгоно.
- Checkov `BC_SKIP_MAPPING=TRUE`-тай ажиллана; үгүй бол run бүрд `api0.prismacloud.io` руу хандаж байв.
- Kubescape, Popeye-ийг kind cluster дээр DNS-ийг бүртгэдэг resolver-ээр хэмжсэн. Popeye зөвхөн API server-тэй харилцана. Kubescape нэмээд `github.com`, `release-assets.githubusercontent.com`, `tuf-repo-cdn.sigstore.dev`, мөн run бүрд version-check үйлчилгээ рүү хандана. Version check-ийг унтраасан (`KS_SKIP_UPDATE_CHECK=true`), `--keep-local` нь үр дүнг Kubescape account руу явуулахгүй. Зөвхөн очих хаягийг ажигласан, хүсэлтийн агуулгыг биш.
- Trivy-ийн халхлагдаагүй secret match-ийг finding руу шууд хуулахаа больсон.

## Нотолгоо ба оролт

- `scan` нь `raw/SHA256SUMS`-ийг `sha256sum` форматаар бичнэ, `scan --raw-dir` нь scan-ийн дараа засагдсан, таслагдсан, нэмэгдсэн файлтай хавтсыг татгалзана. Manifest-гүй (гараар цуглуулсан) хавтас өмнөх шигээ ачаалагдана.
- Scanner-ийн гаралт, raw JSON, scan result 256 MiB, policy / attestation / registry файл 16 MiB-ээс хэтрэхгүй. Илүү том файл бол алдаа — хэзээ ч таслаж уншихгүй.
- `-`-ээр эхэлсэн kube context, namespace, замыг scanner-т flag болгон дамжуулахгүй, татгалзана.
- `update` нь lock дахь хувилбарыг download URL-д оруулахаас өмнө шалгана, `tools.lock.yaml`-ийг атомикаар бичнэ, шинэ install суух хүртэл хуучныг хадгална.
- HTML ба audit тайлан хязгаарлагдмал Content-Security-Policy-тай; Chromium-д `--no-sandbox`-ийг зөвхөн root эсвэл контейнерт өгнө.
- Есөн fuzz target нь дөрвөн scanner parser, policy ба attestation файл, registry, lock файлыг хамарна.

## Төслийн өөрийн supply chain

- GitHub Action бүр commit SHA-д пиннэгдсэн (эхний талынх ч), workflow default-аараа зөвхөн унших эрхтэй, бичих эрх зөвхөн хэрэгтэй job-д, container суурь image digest-ээр пиннэгдсэн, пиннээгүй action-ийг татгалздаг repo тохиргоо асаалттай.
- CI нь scanner-уудыг install script-ийг shell рүү дамжуулахын оронд `tatar-kuber update`-ээр суулгана — пиннэсэн хувилбар, шалгагдсан checksum.
- GitHub Action-ийн `version` default нь `latest` биш release tag.
- `SECURITY.md` нь эмзэг байдлыг хаалттай мэдээлэх заавартай.

README богиносч, хэрэгсэл юу хийдэг, яаж туршиж үзэх, цаашид хаашаа явахыг хэлнэ. Командын лавлах, CI gate нэвтрүүлэлт, аюулгүй байдлын загвар, хамрах хүрээ нь `docs/` дахь гарын авлагад (англи, монгол хоёр хэлээр) шилжсэн.

## Мэдэх ёстой зан төлөвийн өөрчлөлт

- `gate` нь өөртэйгөө зөрсөн result-д exit `2` өгнө (өмнө: хүлээн авдаг байсан).
- `scan --raw-dir` нь `SHA256SUMS`-тэй таарахгүй хавтсад exit `2` өгнө.
- Уншигдахгүй `expires`-тэй suppression хэрэглэгдэхгүй.
- `update`-ийн дараа binary нь өөрчлөгдсөн scanner ажиллахгүй.
- Scanner version мөрөндөө хувилбарын дугааргүй бол `doctor`, `scanner_versions` нь `unparsed` гэж харуулна.
