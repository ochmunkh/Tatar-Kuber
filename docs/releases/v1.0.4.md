**Closing the gap this project kept declaring — and the audit document to hand a client.**

`docs/coverage.md` has always named the controls no scanner checks. Declaring a gap is honest; it is not the same as closing one. This release adds the way to close it, and the deliverable that carries the result out of the terminal.

## Manual attestation — `attest`

Some controls cannot be checked by any scanner: a process, a contract, an organisational control, or a configuration nobody has automated. Until now those were named in `docs/coverage.md` and left there.

```bash
tatar-kuber attest create                                   # template for exactly those controls
tatar-kuber attest apply --attestations attestations.yaml   # merge the signed answers
```

A person checks what a scanner cannot, writes the reason, signs it, and sets an expiry. Four decisions make that an audit record rather than a checkbox:

- **An expiry is mandatory.** When it lapses the control counts as unchecked again and `gate` says so by name. An attestation with no expiry gets written once and reads as true forever — the same defect as a suppression with no expiry.
- **`non-compliant` fails the gate**, at or above the control's severity. If a person has confirmed a control is broken, the result has to show it; otherwise attestation becomes a way to write things down and never act on them.
- **It is not a finding.** Attestations live in their own `attestations[]` block, never in `findings`, so `found_by` never claims a scanner saw something it did not. Because `metadata.result_hash` covers only the findings, a human's answer cannot quietly alter the scanners' evidence.
- **Severity comes from the registry**, not from the file. Letting an attestation set its own severity would be a silent way around the gate.

The template ships **unfilled** on purpose: a template pre-filled with `compliant` teaches people to sign without reading. Validation is strict and collects every problem at once — one mistake and nothing is applied, because a half-applied attestation leaves nobody able to say which control is covered.

## The audit deliverable — `report --format audit` and `--format pdf`

`--format html` is a dashboard: filters, collapsible sections, built for a screen. What an auditor hands a client is a different document, so it is a different format.

```bash
tatar-kuber report --input out/scan-result.json --format audit --out audit.html
tatar-kuber report --input out/scan-result.json --format pdf --lang mn --out audit-mn.pdf
```

A paged, self-contained, bilingual report: scope, method, **what did not run**, the score and how it was derived, the manually attested controls, and the findings grouped by canonical control with their remediation. It loads no scripts, no external CSS, no fonts and no images — a report travels by email and sits in an archive, and a document that fetches external resources looks like something else a year later. A test enforces that.

**TATAR-Kuber does not write PDF itself.** It converts with a headless browser or `wkhtmltopdf` already on the machine. That is a deliberate trade: a Go PDF library would double the dependency count — in this project the dependency count is a supply-chain property — and bring Cyrillic font embedding with it, which is a new way to fail silently. **If no converter is found the command refuses**, names what it looked for, and points at `--format audit` plus the browser's own Print → Save as PDF. It does not write an empty file and call it done.

## Where to start — `top`

```bash
tatar-kuber top --input out/scan-result.json
```

Two tables: the workloads carrying the most weight (summed by severity, not counted), and the controls that hit the most distinct resources. The second one usually matters more — one control failing across thirty workloads is one fix, not thirty.

## Fixes — the tool was misdescribing itself

Every item here was working, green, and producing output. None of them turned red.

- **The binary reported the wrong version.** After v1.0.3 shipped, `master` sat on `1.0.3-dev` for fourteen commits: a build from that tree reported `1.0.3` while not being v1.0.3, and wrote that into every report. The existing test only compared the two version constants to each other — both were equally stale, so it stayed green. A new test reads the published releases and requires `master` to be ahead of the latest one.
- **Two documents contradicted each other about the same pins.** `BLOCKED.md` described checksums as computed from a local download; `tools.lock.yaml` stated in its own header that no value there was computed locally. Both were in the repo, both read as authoritative. It also still claimed the pins covered only linux/amd64, which stopped being true when they were widened to four platforms.
- **The registry misstated when it changed.** `last_updated` read `2026-09-07` while the file had been edited on 2026-10-18, and `docs/coverage.md` repeated that date to the reader. A test now hashes the registry's semantic content — controls, mappings, severities, descriptions, not comments — and fails when the content moves without the date.
- **70 of 75 findings printed no description** while 33 curated descriptions sat unused in the registry. They now reach the report, in both languages, and scanner-written text is no longer overwritten by them.
- **`confidence: HIGH` collapsed three different situations into one word** — 70 single-scanner findings, 4 corroborated by two or more scanners, and 1 heuristic. `confidence_reason` now says which.
- **The suggested ClusterRole asked for Secret read access** with a comment claiming it would not read the values. RBAC cannot do that: `get`/`list` return the whole `data:` field. The permission is gone; pod specs already carry what the scan needs.
- **Mongolian text leaked into English reports** — five strings written by scanner adapters reached `scan-result.json` directly.
- **A docs check could never pass on the maintainer's own machine.** The `.docx`/`.md` parity check compared content that the generator wrote with CRLF against committed LF. CI is Linux-only, so it went unseen for two months.

## Supply chain

- **Checksums are pinned per platform** — twelve values, each read from the release's own published checksum file. One checksum per scanner was correct on linux/amd64 and a mismatch everywhere else, which `update` reported as a corrupt download rather than as an unpinned platform.
- **Pin drift is watched.** Three of four pins went stale within twelve days and nothing said so. A daily job compares each pin against upstream and keeps one issue open. A check that cannot reach the API **fails** rather than reporting "current".
- **Every release ships an SBOM.** A missing tool fails the release instead of silently omitting it.
- **Output permissions tightened** — scan results are a list of a cluster's weaknesses, not world-readable data. Twelve of the twenty open gosec alerts were real fixes of this kind; the remaining eight carry a per-site reason in the code. The Code Scanning board is at **0 open alerts**.

## Windows

`update` now refuses clearly instead of failing obscurely — the catalogue carries no Windows assets — and CI builds and tests on Windows.

## Schema

`confidence_reason` and `attestations[]` are new **optional** fields; `required` has not grown. `pkg/schema/VERSIONING.md` records what counts as a breaking change, and `pkg/schema/compat_test.go` freezes every `required` list so growing one fails the build rather than invalidating every baseline an adopter has committed.

## First outside contribution

13 commits from [fg0x0](https://github.com/fg0x0). `CONTRIBUTING.md` now states what a change has to show: cite the scanner rule's upstream definition, use real fixtures with the version recorded, and report **per-scanner contribution rather than totals**.

**Full changelog:** https://github.com/ochmunkh/Tatar-Kuber/compare/v1.0.3...v1.0.4

# Монголоор

**Энэ төслийн байнга зарладаг байсан цоорхойг хаах — мөн үйлчлүүлэгчид өгөх аудитын баримт.**

`docs/coverage.md` нь ямар ч scanner шалгадаггүй хяналтуудыг үргэлж нэрлэж ирсэн. Цоорхойг зарлах нь шударга, гэхдээ хаасантай адилгүй. Энэ хувилбар нь хаах замыг, мөн үр дүнг терминалаас гаргаж авах баримтыг нэмж байна.

## Гараар батлах — `attest`

Зарим хяналтыг ямар ч scanner шалгаж чадахгүй: процесс, гэрээ, байгууллагын хяналт, эсвэл хэн ч автоматжуулаагүй тохиргоо. Өнөөг хүртэл тэдгээр нь `docs/coverage.md`-д нэрлэгдээд тэндээ үлддэг байв.

```bash
tatar-kuber attest create                                   # яг тэр хяналтуудын загвар
tatar-kuber attest apply --attestations attestations.yaml   # гарын үсэгтэй хариултыг нэгтгэх
```

Scanner чадахгүй зүйлийг хүн шалгаж, үндэслэлээ бичиж, гарын үсгээ зурж, хугацаа тавина. Үүнийг галочка биш, аудитын бүртгэл болгож байгаа дөрвөн шийдвэр:

- **Хугацаа заавал.** Дуусмагц хяналт дахин шалгагдаагүйд тооцогдож, `gate` түүнийг нэрээр нь хэлнэ. Хугацаагүй баталгаа нэг удаа бичигдээд үүрд үнэн мэт уншигдана — хугацаагүй suppression-тай яг ижил согог.
- **`non-compliant` нь gate-ийг унагаана** — хяналтын severity-ийн түвшинд. Хүн зөрчил байгааг баталсан бол үр дүн түүнийг харуулах ёстой; эс бөгөөс баталгаажуулалт бол бичээд мартах арга болно.
- **Энэ нь олдвор биш.** Attestation нь тусдаа `attestations[]` дотор амьдарна, `findings`-д хэзээ ч орохгүй — тиймээс `found_by` нь scanner хараагүй зүйлээ харсан гэж хэлэхгүй. `metadata.result_hash` нь зөвхөн олдворыг хамардаг тул хүний хариулт scanner-ийн нотолгоог чимээгүй өөрчилж чадахгүй.
- **Severity нь бүртгэлээс** ирнэ, файлаас биш. Attestation-д өөрийн severity тавих боломж өгөх нь gate-ийг тойрох чимээгүй зам болно.

Загвар нь **зориуд бөглөөгүй** гарна: урьдчилан `compliant` гэж бичсэн загвар нь хүнийг уншилгүй баталдаг болгоно. Шалгалт хатуу бөгөөд алдаа бүрийг нэг дор цуглуулна — нэг ч алдаа байвал юу ч хэрэглэгдэхгүй, учир нь хагас хэрэгжсэн баталгаа нь аль хяналт хамгаалагдсаныг хэн ч хэлж чадахгүй төлөв үүсгэнэ.

## Аудитын deliverable — `report --format audit` ба `--format pdf`

`--format html` бол дэлгэцийн самбар: шүүлтүүр, задардаг хэсэгтэй. Аудиторын үйлчлүүлэгчдээ өгдөг зүйл бол өөр баримт, тиймээс өөр формат.

```bash
tatar-kuber report --input out/scan-result.json --format audit --out audit.html
tatar-kuber report --input out/scan-result.json --format pdf --lang mn --out audit-mn.pdf
```

Хуудаслагдсан, бие даасан, хоёр хэлт тайлан: хамрах хүрээ, арга зүй, **юу ажиллаагүй**, оноо ба түүний гарал, гараар баталсан хяналтууд, canonical хяналтаар бүлэглэсэн олдворууд засах арга хэмжээтэйгээ. Скрипт, гадаад CSS, шрифт, зураг аль нь ч татагдахгүй — тайлан имэйлээр явж архивт үлддэг, гадаад нөөц татдаг баримт жилийн дараа өөр юм болж харагдана. Үүнийг тест барина.

**TATAR-Kuber нь PDF-ийг өөрөө бичдэггүй.** Машин дээр байгаа headless хөтөч эсвэл `wkhtmltopdf`-ээр хөрвүүлнэ. Энэ бол ухамсартай сонголт: Go-гийн PDF сан нэмбэл гадаад хамаарал хоёр дахин нэмэгдэх бөгөөд — энэ төслийн хувьд хамаарлын тоо бол нийлүүлэлтийн сүлжээний шинж чанар — кирилл үсэгт шрифт шигтгэх асуудал дагалдана, тэр нь чимээгүй эвдрэх шинэ арга юм. **Хөрвүүлэгч олдохгүй бол команд татгалзаж**, юу хайснаа нэрлээд, `--format audit` болон хөтчийн Print → Save as PDF-ийг зааж өгнө. Хоосон файл гаргаад "болов" гэж хэлэхгүй.

## Юунаас эхлэх вэ — `top`

Хоёр хүснэгт: хамгийн их ачаа үүрсэн ажиллагаанууд (ноцтой байдлаар жигнэсэн, тоолсон биш), ба хамгийн олон өөр объектод тусч байгаа хяналтууд. Ихэвчлэн хоёр дахь нь чухал нь — гучин ажиллагаа дээр унасан нэг хяналт бол гучин засвар биш, НЭГ засвар.

## Засвар — хэрэгсэл өөрийгөө худал тайлбарлаж байв

Доорх зүйл бүр ажиллаж, ногоон байж, үр дүн гаргаж байсан. Аль нь ч улаан болоогүй.

- **Binary өөрийгөө буруу хувилбараар танилцуулж байв.** v1.0.3 гарсны дараа `master` нь `1.0.3-dev` дээр арван дөрвөн commit сууж байсан: тэр модоос угсарсан хүн `1.0.3` гэж уншина, гэтэл энэ нь v1.0.3 биш, бас тайлан бүрт тэр тоо бичигдэнэ. Байсан тест нь зөвхөн хоёр тогтмолыг хооронд нь харьцуулдаг байсан — хоёулаа адилхан хоцорсон тул ногоон хэвээр. Шинэ тест нь гарсан хувилбаруудыг уншиж, `master` тэднээс өмнө явж байхыг шаардана.
- **Хоёр баримт нэг л түгжээний талаар бие биенээ үгүйсгэж байв.** `BLOCKED.md` нь checksum-ыг локал татсан файлаас бодсон гэж тайлбарласан; `tools.lock.yaml` нь толгойдоо тэнд локал бодсон утга нэг ч байхгүй гэж бичсэн. Хоёулаа repo дотор, хоёулаа эрх мэдэлтэй мэт уншигдана. Мөн түгжээ зөвхөн linux/amd64-д хамаарна гэж бичсэн хэвээр байсан нь дөрвөн платформ руу өргөссөний дараа худал болсон.
- **Бүртгэл сүүлд хэзээ өөрчлөгдсөнөө худал хэлж байв.** `last_updated` нь `2026-09-07` гэж уншигдаж байхад файл 2026-10-18-нд засагдсан байсан, `docs/coverage.md` тэр огноог уншигчид давтан хэлж байв. Одоо тест нь бүртгэлийн утга санааны агуулгыг — хяналт, зураглал, severity, тайлбар, сэтгэгдлийг биш — hash-даж, агуулга хөдөлсөн атлаа огноо хөдлөөгүй бол унана.
- **75 олдвороос 70 нь тайлбаргүй хэвлэгдэж байв**, гэтэл бүртгэлд 33 сонгон бичсэн тайлбар хэрэглэгдэхгүй сууж байв. Одоо тэдгээр нь тайланд хоёр хэлээр хүрнэ, scanner-ийн өөрийнх нь бичсэн текстийг дарж бичихгүй.
- **`confidence: HIGH` нь гурван өөр нөхцөлийг нэг үгэнд нийлүүлж байв** — 70 нь ганц scanner, 4 нь хоёр ба түүнээс олон scanner-ээр батлагдсан, 1 нь эвристик. `confidence_reason` одоо аль нь болохыг хэлнэ.
- **Санал болгож байсан ClusterRole нь Secret унших эрх гуйж** байсан бөгөөд "утгыг нь уншихгүй" гэсэн тайлбартай байв. RBAC дээр энэ боломжгүй: `get`/`list` нь `data:` талбарыг бүхэлд нь буцаана. Эрхийг нь хассан; шаардлагатай мэдээлэл pod-ийн тодорхойлолтод аль хэдийн байдаг.
- **Англи тайланд монгол үг орж байв** — scanner-ийн адаптерын бичсэн таван мөр шууд `scan-result.json` руу хүрч байсан.
- **Баримтын шалгалт арчилагчийн өөрийнх нь машин дээр хэзээ ч давахгүй байв.** `.docx`/`.md` тулгах шалгалт нь генераторын CRLF-ээр бичсэн агуулгыг commit хийсэн LF-тэй харьцуулдаг байв. Автомат шалгалт зөвхөн Linux дээр ажилладаг тул хоёр сар харагдаагүй.

## Нийлүүлэлтийн сүлжээ

- **Checksum платформ тус бүрээр түгжигдэв** — арван хоёр утга, тус бүр нь release-ийн өөрийнх нь нийтэлсэн checksum файлаас уншигдсан. Scanner бүрт нэг checksum нь linux/amd64 дээр зөв, бусад бүх платформ дээр зөрж, `update` түүнийг "эвдэрсэн татаж авалт" гэж мэдээлдэг байв — түгжээгүй платформ гэж биш.
- **Түгжээ хоцрохыг харж байна.** Дөрвөөс гурав нь арван хоёр хоногийн дотор хоцорсон атлаа хэн ч хэлээгүй. Өдөр тутмын ажил upstream-тэй тулгаж нэг issue нээлттэй барина. API-д хүрч чадаагүй шалгалт нь "цэгцтэй" гэж хэлэхгүй, **унана**.
- **Release бүр SBOM-той гарна.** Хэрэгсэл байхгүй бол release чимээгүй орхихын оронд унана.
- **Гаралтын эрх чангарлаа** — шалгалтын үр дүн бол кластерын сул талуудын жагсаалт, нийтэд уншуулах өгөгдөл биш. Хорин нээлттэй gosec анхааруулгаас арван хоёр нь яг ийм төрлийн жинхэнэ засвар байв; үлдсэн найманд нь кодонд нэг бүрчлэн шалтгаан бичигдсэн. Code Scanning самбар дээр **0 нээлттэй анхааруулга**.

## Windows

`update` нь ойлгомжгүй унахын оронд тодорхой татгалздаг болов — каталогт Windows-ийн файл байхгүй — мөн автомат шалгалт Windows дээр угсарч, тест ажиллуулна.

## Гаралтын бүтэц

`confidence_reason` ба `attestations[]` нь шинэ **сонголттой** талбарууд; `required` өсөөгүй. `pkg/schema/VERSIONING.md` нь юуг эвддэг өөрчлөлт гэж үзэхийг бичсэн, `pkg/schema/compat_test.go` нь `required` жагсаалт бүрийг царцаасан тул аль нэгийг өсгөх нь adopter-ийн commit хийсэн baseline бүрийг хүчингүй болгохын оронд build-ийг унагана.
